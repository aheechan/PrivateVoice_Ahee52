# 更正：v4 的"底噪"其实是削波，不是模型噪声

> 2026-11-02，针对 `v4_upstream.wav` 的底噪反馈

## 1. 结论

`v4_upstream.wav` 里那个"严重的底噪"是 **86% 的削波失真**，不是模型生成的噪声。

原因：上游 v4 的 `TTS.run()` 返回的是 **int16 量纲的 float**（峰值 11128、p99 3914），
不是 ±1.0 的归一化浮点。我们直接把它当 ±1.0 写进 16bit WAV，于是 86% 的采样点被削在
0 dBFS 上，听起来就是"沙沙的底噪/糊"。

## 2. 实测

| 文件 | 采样率 | 峰值 | 削波比例 | 4–8k | 8–12k | 12–16k | 16–24k |
|---|---|---|---|---|---|---|---|
| `v3_output.wav` | 24k | 0.477 | 0.00% | 0.44% | 0.62% | — | — |
| `v4_upstream.wav`（修复前） | 48k | **1.000** | **85.93%** | 5.51% | 2.79% | 1.16% | 1.58% |
| `v4_output.wav`（修复后） | 48k | 0.575 | 0.00% | 0.60% | 0.35% | 0.00% | 0.00% |

修复前那 5.5% 的"高频"，**大部分是削波产生的谐波**，不是真实语音高频。

## 3. 修复

`app/core/tts.py` 的 `_stream_upstream()` 里，对每个块判断量纲：

```python
peak = float(np.max(np.abs(arr)))
if peak > 2.0:          # 上游 v4 是 int16 量纲
    arr = arr / 32768.0
```

之后仍走原有的 -1 dBTP 限幅与重采样，输出峰值 0.575（-4.8 dBFS），零削波。

## 4. 需要更正之前的说法（重要）

我上一轮说"v4 高频比 v3 多约 10 倍、不再发闷"——**那个结论是错的**，
它是被削波污染后的测量。修好量纲后再测：

- v4 vs v3 的 4–8k 能量：0.60% vs 0.44%，8–12k：0.35% vs 0.62%
- **提升很小，甚至略低**

也就是说：**"闷"的根子还是素材**（参考音频 4–8k 只有 0.2%、8–12k 0.9%），
v4 解决的是官方说的"v3 金属感/非整数倍上采样"，不解决带宽。

## 5. 想真正不闷，只有三条路

1. **重录素材**（最有效）：48kHz、安静房间、关降噪/美颜，3–5 分钟
2. **EQ 补偿**：播放端 +3~4dB 高架 @5kHz，能听出亮度但会放大底噪
3. **24k→48k 超分**：仓库里有 `tools/AP_BWE_main`，补高频但可能带人工味
